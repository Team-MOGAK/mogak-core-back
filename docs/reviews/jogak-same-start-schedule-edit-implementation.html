Jogak 현재 일정 PATCH 편집 구현 제어

목적
현재 일정의 요일·종료일 PATCH 편집을 안전하게 구현·검증한다.
사용자
Jogak 일정을 편집하는 모바일 사용자와 API 유지보수 개발자
문제
기존 PUT 계약은 부분 수정 의도와 맞지 않고, 동일 시작일 일정 수정도 거부된다.
핵심 흐름
PATCH 검증 → KST 현재 일정 제자리 갱신 → 요일 교체 → 실행 이력 보존 → 검증
기준 설계
설계 승인됨 (2026-08-18 00:56 KST)
상태
구현 완료

승인 기준

PATCH에서 KST 현재 schedule 전체를 기존 계약에 맞게 교체하고, 후속 일정 경계를 보존하면서 제자리 갱신한다. 기존 dailyJogak/실행 기록과 제목 스냅샷은 변경하지 않는다.

현재 구현

PATCH /api/jogaks/:jogakId가 title 또는 전체 schedule을 받는다. PUT 수정 경로는 제거됐다. schedule PATCH는 KST 현재 일정을 선택해 행 ID·시작일을 유지한 채 타입·종료일·요일을 갱신한다.

구현 상태

구현 완료 — 후속 일정이 있으면 종료일 생략은 전날로 보정하고, 겹치는 명시 종료일은 J009으로 거부한다.

이슈 등록부

확인된 구현 이슈와 처리
상태증상·영향조치·검증
해결됨종료일 생략 PATCH가 후속 일정과 겹쳐 발생을 중복할 수 있었다.후속 시작일 전날로 자동 제한하고, 명시적 겹침은 J009으로 거부한다. 단위·DB 통합 테스트를 추가했다.
해결됨중첩 schedule의 생략 필드 의미가 불명확했다.기존 계약을 따라 schedule은 전체 교체 객체로 확정하고, weekdays 누락은 Z005로 거부한다.

검증 근거

pnpm test -- --runInBand test/mogaks/presentation/jogaks.controller.spec.ts test/mogaks/application/jogaks.service.spec.ts: 19개 통과. pnpm typecheck, 변경 파일 ESLint·Prettier, git diff --check: 통과. 독립 읽기 전용 검토에서 발견한 3개 결함을 수정했다.

검증 공백

DB 통합 테스트는 테스트 DB의 CREATE SCHEMA drizzle 권한 오류로 global setup에서 실행되지 못했다. DB 권한 복구 뒤 재실행이 필요하다.

잔여 위험

PATCH 계약 전환은 GitHub issue #6의 범용 JSON Merge Patch RFC와 별개다. 기존 모바일 클라이언트는 PUT 대신 PATCH 계약으로 전환해야 한다.

최종 코드 리뷰

자기 변경에 대한 읽기 전용 재검토 완료. PATCH 계약, KST 활성 일정 선택, 후속 일정 경계, schedule 행 ID·시작일 보존, WEEKLY→ONCE 정리, 실행·제목 스냅샷 보존을 실제 코드·테스트와 대조했다.
