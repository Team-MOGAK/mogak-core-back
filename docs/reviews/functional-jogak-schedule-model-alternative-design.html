목표와 비목표

일급 컬렉션의 규칙 응집은 유지하고, 구현 수단만 클래스에서 discriminated union과 순수 함수로 바꾼다.

비목표: 성능 수치를 보장하는 것, API·DB·repository port 변경, 캐시·메모이제이션 도입, 날짜 branded type 도입, 일정 의미와 대표 선택 순서 변경.

타입·생성·선택 규칙
영역 규칙
ONCE effectiveTo: null, weekdays: []이며 정확히 effectiveFrom에만 발생한다.
WEEKLY 유효하고 중복 없는 weekday가 하나 이상이며, 종료일은 없거나 시작일 이후다.
배열 경계 입력 weekday와 반환 DTO의 weekday는 모두 복사한다. 호출자 mutation이 검증된 일정에 영향을 주지 않는다.
이력 선택 effectiveFrom ASC, scheduleId ASC 정렬을 유지한다. 대표는 활성 WEEKLY → 당일 ONCE → 최신 이력, 수정 대상은 오늘 현재 일정, 후속은 더 늦은 시작일의 첫 일정이다.
실패 사용자 입력은 기존 DomainException, 손상된 persistence row는 원인을 보존한 MogakPersistenceException으로 실패한다.

구현 범위

  1. jogakSchedule.vo.ts의 ValidatedJogakSchedule을 ONCE/WEEKLY discriminated union으로 구체화한다.
  2. jogakSchedule.policy.ts에서 weekday 검증·복사, 일정 생성, 발생·활성·이력 선택을 순수 함수로 제공한다.
  3. jogaks.service.ts는 plain schedule을 그대로 보관하고, identity 기반 재탐색과 toSnapshot() 호출을 제거한다.
  4. onceSchedule.vo.ts, routineSchedule.vo.ts, jogakWeekdays.vo.ts, jogakSchedules.vo.ts를 제거하고 함수형 API 기준으로 테스트를 교체한다.
성능 판단: 현재 코드에서 클래스가 확정된 병목이라는 측정값은 없다. 이 변경의 주효과는 인스턴스·snapshot·이력 wrapper 할당 감소와 코드 단순화다. DB I/O와 날짜별 발생 순회는 그대로 남는다.

위험과 방지책

plain object는 수정하기 쉬우므로, 생성 함수에서 weekday를 복사하고 response 경계에서도 다시 복사한다. readonly만으로 런타임 freeze를 보장하지는 않지만, 현행 외부 계약에도 freeze는 없으므로 추가 비용 없이 복사 경계를 유지한다.

함수로 옮기면서 선택 순서가 바뀌지 않도록, record 정렬은 service에 유지하고 선택 함수는 정렬된 입력을 전제로 한다. 동일 시작일 tie-break는 scheduleId ASC를 계속 service에서 결정한다.
