구현 제어 단계: 운영 제어 보류

레거시 삭제 연쇄 복구 구현 제어

목적
조각 계층을 삭제하고 게시글은 독립적으로 보존한다.
핵심 흐름
FK 보정 → 부모 삭제 → post 보존 → 상세의 상위 정보 null 반환

기준: 설계 승인본

구현 · 검증 · 리뷰

현재 구현

  • v1 DB cascade SQL은 실행 금지로 표시하고, v2가 조각 계층 FK를 ON DELETE NO ACTION으로 보정한다.
  • 모다랏·모각·조각 삭제 repository는 하나의 트랜잭션에서 일정 요일 → 일정 → 일일 조각 → 조각 → 모각 → 모다랏 순으로 명시 삭제한다.
  • post.daily_jogak_id FK를 제거하고 값과 post 하위 FK는 유지한다. 일반 index는 추가하지 않고 UNIQUE CONSTRAINT만 둔다.
  • 게시글 상세은 상위 실행·조각·모각을 LEFT JOIN하며 삭제된 원본 식별자는 null로 응답한다.
  • DB 오류는 code·constraint·table만 구조화 로그에 남긴다.

검증 근거

  • focused Jest 4 suite, 34 test 통과.
  • pnpm typecheck, 변경 파일 ESLint, pnpm build, migration script syntax 통과.
  • 스키마 테스트가 조각 계층 FK의 onDelete: 'no action'을 확인한다.

이슈 등록

해결: DB constraint 식별자를 안전한 구조화 로그에 남긴다.

열림: 현재 환경에 DATABASE_URL이 없어 새 애플리케이션 삭제 트랜잭션의 PostgreSQL 통합 테스트는 실행되지 않았다. 운영 SQL 실행 전 v2를 임시 레거시 DB에 적용하고, 모다랏·모각·조각 삭제 뒤 post 보존을 확인한다.

잔여 위험: 실제 운영 DB의 constraint·데이터 상태와 DDL 잠금 시간은 배포 전 카탈로그 조회로 확인해야 한다. 전체 lint는 별도 worktree의 ESLint root 충돌로 실패했고 변경 파일 lint는 통과했다.
