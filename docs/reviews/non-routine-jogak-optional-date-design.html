목적
루틴이 아닌 조각을 날짜 입력 없이 생성할 수 있게 한다.

변경 모델

POST /api/jogaks에서 isRoutine: false와 생략된 today를 허용한다. 이 경우 Jogak 행만 저장하고 jogak_schedules나 실행 행은 만들지 않는다. 서버가 오늘 날짜를 자동으로 넣지 않는다.

기존 호환성은 유지한다. 즉 isRoutine: false와 명시 today가 함께 오면 현재처럼 해당 날짜의 ONCE 일정을 만들어 생성한다. 명시 schedule 형식도 유지한다.

범위 경계

핵심 불변식

응답 모델 위험: 현재 생성 응답은 일정 필드를 항상 반환한다. 무일정 생성에서는 이 필드를 nullable 또는 생략으로 표현해야 하며, 기존 일정 생성 응답의 값은 바꾸지 않는다.
  • 기본 날짜를 절대 생성하지 않는다.
  • 무일정은 명시적인 isRoutine: false에만 허용한다. isRoutine 누락과 루틴의 시작일 누락은 계속 거부한다.
  • 무일정 조각은 일정 기준 용량 제한과 날짜별 조각 발생에 포함되지 않는다.
  • dailyJogak을 나중에 추가하는 방식은 이 변경의 구현 범위·공개 계약에 포함하지 않는다.

검증 계획

  • isRoutine: false, today 생략 요청이 201로 조각만 저장하는지 확인한다.
  • 이 응답이 일정 없음 상태를 명확히 표현하고, 날짜별 조각 조회에는 나타나지 않는지 확인한다.
  • 명시 today와 명시 schedule의 기존 ONCE 생성 회귀를 확인한다.
  • 루틴의 시작일·요일 검증과 executionDate start의 현재 동작이 바뀌지 않는지 확인한다.

설계 이해 점검

design-control-state: 미실시. 범위(Q1), 기본값 금지(Q2), 경계(Q3), 회귀 검증(Q4)을 다룬다. 권한·외부 효과·복구는 해당하지 않아 면제한다.
