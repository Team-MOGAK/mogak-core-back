유효하지 않은 요청 입력 관측성 설계

목적
도메인 예외를 운영 로그만으로 재현·진단할 수 있게 한다.
사용자
서버 장애와 API 입력 오류를 조사하는 백엔드 운영자·개발자.
문제
현재 GlobalExceptionFilter 로그에는 오류 코드만 있어 어떤 요청값이 거절됐는지 알 수 없다. 서비스 도메인 요청값은 운영 진단을 위해 원문 기록이 필요하다.
핵심 흐름
요청 수신 → DomainException → 전역 필터가 params/query/body를 재귀적으로 정제해 warn 로그에 기록 → 민감 필드 값 제거 → 기존 오류 응답 반환.
생성·갱신: 2026-08-17
변경 모델핵심 위험검증설계 이해 점검승인

변경 모델

  1. 모든 DomainException 로그에 HTTP method, 정적 route, params/query/body를 추가한다. 매핑 결과 코드가 Z005인지 여부는 기록 조건이 아니다.
  2. body·query·params 객체와 배열을 재귀적으로 정제한다. 제외 키는 대소문자·camel/snake/kebab 표기를 정규화해 검사하고 로그 객체에서 키와 값 전체를 제거한다.
  3. 인증값인 authorization, token, password, secret, cookie를 포함하는 키와 파일·multipart 원문은 로그에 남기지 않는다. 그 외 서비스 도메인 값은 원문을 남긴다.
  4. 민감하지 않은 값은 기록하되 payload 깊이·배열 길이·문자열 길이를 제한한다. 초과 부분은 [TRUNCATED]다.
  5. 기존 HTTP 응답 envelope와 상태 코드는 바꾸지 않는다. HttpException, 처리되지 않은 예외, rate-limit 로그에는 요청 원문을 추가하지 않는다.

핵심 불변조건

서비스 범위에서 보호해야 할 인증값은 키 이름도 값도 로그에 남지 않는다. 그 외 도메인 요청값은 운영 진단을 위해 원문을 남긴다. 정제 로직 자체가 다시 예외를 내지 않는다.

범위 밖

클라이언트 오류 응답에 입력값·스키마 상세를 추가하지 않으며, 성공 요청과 Z005 이외의 오류에 새 payload 로그를 추가하지 않는다.

검증 계획

전역 필터 단위 테스트에서 Z005와 일반 도메인 오류 모두 body/query/params 원문이 남는지, 중첩 access token·authorization의 키와 값이 모두 없는지, 크기 제한이 [TRUNCATED]가 되는지, 기존 HTTP 응답 계약이 유지되는지를 고정한다.

미실시

승인 상태

재승인 필요. 기존 승인은 Z005에 한정됐다. 2026-08-17 사용자 피드백에 따라 모든 DomainException으로 로그 범위를 넓혔으므로, 이 변경 범위에 대한 별도 승인이 필요하다. 서비스 도메인 요청값은 원문 기록하고, 인증값과 multipart 원문은 키와 값 모두 로그에서 제거한다.
