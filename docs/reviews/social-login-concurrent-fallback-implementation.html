목적
동일 소셜 계정의 로그인·가입 재개를 복구한다.
사용자
가입 재시도 사용자, 모바일 프런트, 인증 운영 담당자.
문제
경쟁 로그인과 null role이 가입 재개를 막고 프런트가 재개 상황을 구분할 수 없다.
핵심 흐름
identity 확인 → 상태 복구 → 세션 발급 → 구분 코드로 프런트에 전달.

기준 설계: 설계 문서 (2026-08-17 재승인됨)

구현 기준

승인된 보완 범위: exact identity fallback, 가입 필수 정보 기반 null role 정규화, AUTH_SIGNUP_RESUME_REQUIRED 성공 응답 코드와 권한 경계 테스트.

현재 구현

두 unique 충돌 후 exact identity를 재조회하며 PENDING 기존/경쟁 승자는 세션과 가입 재개 코드를 받는다. 이메일만 같은 다른 identity 및 post-insert duplicate-email 재조회 미발견은 U012이며 세션을 만들지 않는다.

null role은 가입 요청과 같은 trimmed nickname 2~10자, jobId, addressId, 활성 필수 동의의 agreed=true를 모두 확인한다. 해당 user의 role IS NULL일 때만 userId와 함께 조건부 갱신하고 재조회한다.

이슈 등록

해결됨 — 권한 승격 위험: nickname 1자·11자, job/address 누락, 필수 동의 행 누락을 PENDING으로 검증했다. U012 race branch와 CAS SQL predicate, 가입 재개 응답의 access/refresh token도 집중 테스트로 확인했다.

검증 증거

pnpm typecheck 통과. application/repository focused test 2 suites, 32 tests 통과. controller HTTP contract test 1 suite, 5 tests 통과. git diff --check 통과.

검증 공백

실제 PostgreSQL 동시 요청과 운영 DB null role 표본 확인은 남아 있다.

잔여 위험

활성 필수 동의 구성이 변경되면 레거시 null role 계정이 PENDING으로 분류될 수 있다. 이는 승인된 현재 활성 기준이다.

리뷰

상태: 검토 완료. 자기 변경을 설계·구현 기록 및 최종 diff와 대조했다. nickname 2~10자 경계, exact identity 기반 U012 보존, user_id AND role IS NULL CAS, AUTH_SIGNUP_RESUME_REQUIRED의 200 응답과 tokens 전달을 확인했으며 concrete finding은 없다.

검증 한계: 실제 PostgreSQL 동시 충돌과 운영의 null role 표본은 아직 확인하지 못했다.
