이전 구현 기준 (대체됨)

이 섹션 이하의 내용은 이메일 unique와 U012 연결 계약을 사용하던 이전 fallback 구현의 역사 기록이다. 현재 구현 기준은 위 최신 provider별 독립 소셜 계정 문서와 구현 제어 문서를 따른다.

이전 구현 기록

당시에는 두 unique 충돌 후 exact identity를 재조회하며 PENDING 기존/경쟁 승자는 세션과 가입 재개 코드를 받았다. 이메일만 같은 다른 identity 및 post-insert duplicate-email 재조회 미발견은 U012이며 세션을 만들지 않았다.

null role은 가입 요청과 같은 trimmed nickname 2~10자, jobId, addressId, 활성 필수 동의의 agreed=true를 모두 확인했다. 해당 user의 role IS NULL일 때만 userId와 함께 조건부 갱신하고 재조회했다.

이전 이슈 기록

당시 해결됨 — 권한 승격 위험: nickname 1자·11자, job/address 누락, 필수 동의 행 누락을 PENDING으로 검증했다. U012 race branch와 CAS SQL predicate, 가입 재개 응답의 access/refresh token을 집중 테스트로 확인했다.

이전 검증 증거

pnpm typecheck 통과. application/repository focused test 2 suites, 32 tests 통과. controller HTTP contract test 1 suite, 5 tests 통과. git diff --check 통과.

이전 검증 공백

실제 PostgreSQL 동시 요청과 운영 DB null role 표본 확인은 남아 있었다.

이전 잔여 위험

활성 필수 동의 구성이 변경되면 레거시 null role 계정이 PENDING으로 분류될 수 있다는 위험이 기록되어 있었다.

이전 리뷰

상태: 대체됨. 이 기록의 exact identity 기반 U012, AUTH_SIGNUP_RESUME_REQUIRED, 이메일 unique 전제는 현재 계약이 아니다.

현재 provider 분리·T006·U017 계약은 최신 문서를 확인한다.
