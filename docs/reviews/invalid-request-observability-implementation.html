유효하지 않은 요청 입력 관측성 구현 제어

목적
Z005 입력 검증 실패를 비밀값 노출 없이 진단한다.
사용자
API 입력 오류를 조사하는 백엔드 운영자·개발자.
문제
기존 로그에는 오류 코드만 있어 거절된 원문 요청값을 확인할 수 없다.
핵심 흐름
Z005 → 원문 params/query/body 재귀 정제 → 전역 warn 로그 → 기존 Z005 응답.

승인 기준선: /Users/hyunseok/IdeaProjects/mogak-core-back/docs/reviews/invalid-request-observability-design.html · 승인: 2026-08-17, 사용자 “ㄱㄱㄱㄱㄱ”

현재 구현

GlobalExceptionFilter가 모든 Z005의 원문 params/query/body를 기록한다. authorization, token, password, secret, cookie를 포함하는 중첩 키는 키와 값 모두 제거하고, multipart body도 기록하지 않는다. 깊이·배열·객체·문자열 크기 제한은 [TRUNCATED]다.

구현 상태

메인 병합 후 apps/api/src/core/common/error/domainException.ts의 core 예외 계약과 apps/api/src/api/common/http/globalException.filter.ts의 HTTP 매핑을 유지했다. 매핑 결과가 Z005일 때 blacklist 기반 정제를 적용한다.

이슈 등록부

해결됨: 메인의 API/core 계층 분리와 기존 예외 이동이 충돌했다. 메인의 core 오류 코드 → HTTP 오류 매핑을 유지하고, 전역 필터와 테스트에 원문 로그 기능을 이식했다.
