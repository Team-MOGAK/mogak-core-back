유효하지 않은 요청 입력 관측성 구현 제어

목적
도메인 예외를 비밀값 노출 없이 진단한다.
사용자
API 입력 오류를 조사하는 백엔드 운영자·개발자.
문제
기존 로그에는 오류 코드만 있어 거절된 원문 요청값을 확인할 수 없다.
핵심 흐름
DomainException → 원문 params/query/body 재귀 정제 → 전역 warn 로그 → 기존 오류 응답.

승인 기준선: /Users/hyunseok/IdeaProjects/mogak-core-back/docs/reviews/invalid-request-observability-design.html · 승인: 2026-08-17, 사용자 “ㅇㅇ ㄱ”

현재 구현

GlobalExceptionFilter가 모든 DomainException의 원문 params/query/body를 기록한다. authorization, token, password, secret, cookie를 포함하는 중첩 키는 키와 값 모두 제거하고, multipart body도 기록하지 않는다. 깊이·배열·객체·문자열 크기 제한은 [TRUNCATED]다.

구현 상태

메인 병합 후 apps/api/src/core/common/error/domainException.ts의 core 예외 계약과 apps/api/src/api/common/http/globalException.filter.ts의 HTTP 매핑을 유지했다. 매핑 결과 코드와 무관하게 모든 DomainException에 기존 정제를 적용한다.

이슈 등록부

해결됨: 메인의 API/core 계층 분리와 기존 예외 이동이 충돌했다. 메인의 core 오류 코드 → HTTP 오류 매핑을 유지하고, 전역 필터와 테스트에 원문 로그 기능을 이식했다.

검증 증거·공백

도메인 예외 필터 단위 테스트(13 tests), 전체 Jest(53 suites / 206 tests), pnpm typecheck, pnpm lint, pnpm format:check는 통과했다.

리뷰

독립 검토 완료 · 보완 완료. 모든 DomainException으로 로그 범위를 넓히되, 인증 키 재귀 제거, multipart 본문 제외, 정제 실패 시 기존 응답 유지, core 예외의 HTTP 매핑 보존을 확인했다. 최상위 요청 필드 getter가 예외를 던지는 경우도 해당 필드만 생략하도록 보완했다.

리뷰 확인과 검증 경계
항목결과
원문 로그 경계모든 DomainException에서 params/query/body 원문은 남기고 승인된 인증 키·multipart 본문은 생략
core 오류 매핑기존 DomainErrorCode → AppErrorCode HTTP 계약을 보존한 채 로깅
실패 안전성최상위 params/query/body 접근 오류는 해당 필드만 생략하고 원래 응답을 유지

잔여 공백없음

개발자 운영 이해

미실시. 새 로그는 request.params, request.query, request.body에서 확인하며, 인증 키나 multipart 본문이 없으면 원문을 찾으려 시도하지 않는다.
