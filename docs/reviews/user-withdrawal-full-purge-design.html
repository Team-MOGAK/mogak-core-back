회원 탈퇴: 동기 전체 삭제

상태: 승인됨 / 구현 중

목적

회원 탈퇴 요청 안에서 회원과 회원이 소유하거나 작성한 관계 데이터를 앱 코드가 명시적으로 삭제한다. DB FK cascade는 삭제 완결성의 전제가 아니다.

HTTP 계약

POST /api/auth/withdraw → 204 No Content

응답 본문 및 isDeleted 필드는 반환하지 않는다. 성공은 삭제 완료를 뜻한다.

삭제 순서

  1. 대상 사용자 transaction advisory lock 획득
  2. 대상 모각 실행과 사용자 작성 게시글을 찾고, 게시글 이미지·댓글·좋아요·게시글을 자식부터 삭제
  3. 사용자 작성 댓글·좋아요, 팔로우 양방향, 세션, 소셜 계정, 동의를 삭제
  4. 일정 요일·일정·실행·조각·모각·모다랏을 자식부터 삭제
  5. 마지막으로 users 행을 삭제

동시성 규약

탈퇴는 대상 사용자뿐 아니라, 대상 실행에 연결된 게시글 작성자·댓글 작성자·좋아요 사용자와 팔로우 상대를 하나의 집합으로 먼저 조회해 오름차순으로 pg_advisory_xact_lock 한다. lock 획득 후 모든 삭제 대상은 SQL subquery로 다시 계산한다. 댓글·좋아요 mutation도 작성자, 게시글 작성자, 연결된 모각 소유자를 함께 lock하고, 팔로우는 양쪽 사용자를 함께 lock한다.

대량 계정에서도 bind parameter 제한에 걸리지 않도록 탈퇴 cascade는 JavaScript ID 배열이나 IN (...ids)가 아니라 set-based SQL subquery와 DELETE USING으로 수행한다.

이 lock은 DB 전체에 공유되지만 같은 사용자 key만 충돌한다. transaction commit/rollback 때 자동 해제된다.

범위 밖

외부 오브젝트 스토리지 삭제, 비동기 purge job, lifecycle 상태는 이번 동기 구현에 포함하지 않는다.
