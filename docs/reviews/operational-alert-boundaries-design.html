결정 · 경계 · 불변식 · 검증 · 자기점검

목표·범위

기존 ERROR 전송 동작을 보존하며 기능 내부의 책임과 의존 방향을 명확히 한다.

범위 밖

제품 알림, 신규 provider, incident lifecycle, 공용 library 추출, cloud apply.

확정 설계

사용자 승인: “alerting은 기능 모듈로 두고 domain 계층 없이 가자. 그 기준으로 설계 정리하고 구현 ㄱ. 커밋도 책임 단위로 나눠”. 이 명시적 지시를 현재 설계의 구현 승인으로 기록한다.

apps/alerting, private @mogak/alerting으로 기능과 실행체를 표현한다. application·presentation·infrastructure를 분리하고 domain 계층·Entity·Aggregate를 만들지 않는다. API와 SDK·ESM·이미지 격리를 유지한다. 제품 core/modules나 공용 라이브러리로 추출하지 않는다.

기존 ERROR 웹훅 동작 설계는 전달 계약의 기준으로 유지한다. 이 문서는 책임 경계의 후속 기준이다. 초기 domain 포함 제안은 철회됐다.

실패·복구

성공은 fenced finalize 뒤 ACK. 일시 실패·429·상태 저장 장애·격리 발행 실패는 재시도. 영구 거부는 허용 필드로 격리 후 ACK하며 채널 영구 오류는 disable. 기존 lease·cooldown 및 bounded deadline을 유지한다.

채택하지 않은 대안

domain 계층: 현재 모델 근거 부족. generic notification/external: 기능 책임이 흐려짐. shared core 추출: 단일 consumer 및 SDK/module format 경계 비용.

보존할 계약

  • production API stdout / ERROR / level=50 / alertEligible=true 검증과 malformed·filtered 구분.
  • Discord와 quarantine 허용 필드 및 고정 요약. raw message·stack·request·SQL·실제 path ID·webhook URL 제외.
  • 기존 204 ACK / 503 retry / deadline, 429 cooldown, disable, stale fence, secretVersion, fail-closed 의미와 로그 event·reason 보존.
  • 외부 HTTP는 transaction 밖. at-least-once 중복 가능성과 native DLQ 원본 보존 유지.
  • GCP resource ID·설정값·Firestore schema·큐 상태·producer 식별자 유지. 소스 이름으로 운영 리소스를 재생성하지 않음.
  • 독립 manifest/ESM/SDK/이미지 격리. API runtime에 Google SDK 추가 없음.
실제 GCP apply, IAM 변경, 배포, Discord 전송은 승인 범위에 포함하지 않는다. 이번 변경은 기능·실패 계약을 보존하는 구조 리팩터링이다.

설계 의사결정 상태

완료. 기능명 alerting과 기술 계층 infrastructure를 구분하고 domain 계층 생성을 거부한다는 사용자 결정이 확정됐다. 단일 consumer이므로 공용 추출·범용 notification은 제외한다. 미해결 material frontier 없음. 알림 규칙·사건 상태·담당자·에스컬레이션은 이번 범위 밖이며 실제 요구가 생길 때 별도 판단한다.

실행·검증·커밋 계획

  1. 승인 설계를 먼저 기록한다.
  2. 현재 경로에서 application 계약·안전한 투영·유스케이스와 provider/input 어댑터를 분리한다. 기존 테스트 import와 test double 위치를 함께 이관한다.
  3. apps/alerting과 @mogak/alerting으로 전환하고 workspace·lockfile·Docker·Cloud Build·CI·scripts 참조를 연결한다.
  4. README·runbook에 새 구조와 기존 운영 이름의 보존 이유를 기록한다.
  5. 정적 검증과 독립 no-write 리뷰를 수행하고 구현 기록을 별도 유지한다.

각 단계는 책임별 커밋으로 분리한다. 코드와 관련 기존 테스트 이관은 같은 커밋에 둔다. 기존 PR 커밋을 다시 squash하거나 force rewrite하지 않는다.

실행할 검증: pnpm format:check, pnpm lint, pnpm typecheck, pnpm build, pnpm --filter @mogak/alerting typecheck, pnpm --filter @mogak/alerting build, git diff --check. 새 테스트 추가·실행은 요청되지 않아 제외한다. 빌드 통과는 실제 IAM/Discord 전달을 보증하지 않는다.
