현재 구현

apps/api/src는 api, core, infrastructure, composition으로 분리돼 있다. core와 infrastructure는 core 소유 DomainException(code)을 사용하며, API GlobalExceptionFilter가 기존 AppErrorCode의 HTTP status/code/message로 변환한다. API 전용 예외 클래스는 제거했다.

레이어 루트 참조는 @api, @core, @infra, @composition alias를 사용한다. TypeScript paths와 Jest mapper를 맞추고, build 뒤 tsc-alias가 실행 가능한 dist/**/*.js의 alias를 상대 경로로 치환한다.

이슈 등록부

해결됨 — HTTP 오류 예외 이중화
CoreError와 API DomainException을 하나의 core DomainException으로 통합했다. 대표 404 mapping과 미등록 code의 500 fallback 테스트로 기존 API 계약을 고정했다.
해결됨 — build runtime alias
tsc-alias를 build 단계에 추가했고 dist/**/*.js에 layer alias가 남지 않음을 검사했다. node -e "require('./dist/composition/app.module.js')"로 Node module resolution도 확인했다.
보류 — DB integration 환경
DATABASE_URL이 없어 DB integration은 아직 실행하지 못했다.

검증 증거

  • pnpm format:check 통과
  • pnpm lint 통과
  • pnpm typecheck 통과
  • pnpm build 통과
  • dist/**/*.js의 alias 잔존 없음
  • pnpm test --runInBand 통과: 53 suite, 201 tests

잔여 위험

DB integration은 연결 가능한 DATABASE_URL 환경에서 재실행해야 한다. core feature 간 현재의 좁은 port import는 소비자 소유 gateway로 재소유하는 후속 과제로 남는다.
