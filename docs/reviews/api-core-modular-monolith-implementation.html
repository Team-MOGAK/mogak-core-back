구현 · 검증 · 리뷰

기준선 참조

설계 기준선을 따른다. 구현 중 API, 데이터, 오류 처리 또는 검증 전략이 달라지면 설계 재승인이 필요하다.

현재 구현

기존 src를 apps/api/src로 이동했다. api에는 controller/guard/HTTP·validation, core에는 feature domain/application/port, infrastructure에는 Drizzle·repository·token·storage, composition에는 Nest module binding을 배치했다. core service는 일반 TypeScript class가 되었고 composition factory가 port 구현체를 주입한다. infrastructure의 auth/storage adapter도 API HTTP 예외 대신 core error를 사용한다.

구현 상태

구현 완료. CoreError를 추가하고 API GlobalExceptionFilter가 기존 AppErrorCode로 변환한다. core의 upload port는 Express.Multer.File 대신 BinaryUpload을 사용한다.

이슈 등록부

해결됨 — sandbox HTTP listen 차단
일반 sandbox에서 전체 Jest 실행 시 listen EPERM이 관찰됐다. 권한 있는 환경에서 같은 명령을 재실행해 53 suite/199 test 통과로 코드 문제가 아님을 확인했다.
보류 — DB integration 환경
pnpm test:db --runInBand는 DATABASE_URL is required로 globalSetup 전에 중단됐다. DB URL이 제공된 환경에서 재실행이 필요하다.

검증 공백

pnpm test:db --runInBand는 필요한 DATABASE_URL이 없어 실행되지 않았다. schema/migration SQL 생성 여부와 DB integration 회귀는 연결 가능한 test DB에서 확인해야 한다.

잔여 위험

DB integration이 미검증이다. 또한 core feature 간 현재의 좁은 port import는 유지했으며, 소비자 소유 gateway로의 완전한 재소유는 후속 개선 대상으로 남는다.

구현 제어 상태

구현 완료. 개발자 운영 이해 점검: 미실시 — 구현 사실과 검증 증거만 기록했으며, 실제 운영 진단 시나리오 응답은 아직 관찰하지 않았다.
