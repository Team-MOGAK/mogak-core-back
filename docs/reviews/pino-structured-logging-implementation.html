구현 범위 · 리뷰 · 검증 증거

구현 범위

pino, pino-http, nestjs-pino를 추가했다. AppModule은 Pino HTTP와 전역 예외 필터를 DI로 등록하고, main.ts는 Nest 내부 logger를 Pino로 연결한다.

기존 production Nest Logger 직접 생성 5곳(GlobalExceptionFilter과 Mogak·Post·Social·Consent repository)을 @InjectPinoLogger(클래스명)로 전환했다. 원본 예외는 허용 필드만 추출한 plain object로 변환하고, Pino의 err 필드로 기록한다. DB 오류 식별자는 err.database 아래에만 포함한다.

잠금 후 누락 경고는 중복된 resource 필드 대신 user_not_found_after_lock, jogak_not_found_after_lock, post_not_found_after_lock 이벤트명으로 원인을 직접 표현한다.

로그 계약

요청마다 UUID req.id를 생성한다. HTTP 로그에는 id, method, query를 제거한 path, status만 남긴다. Authorization·cookie·token·password 계열 필드는 redaction하고, LOG_LEVEL은 development에서 debug, 그 외에서 info가 기본값이다.

테스트 조정

전역 필터 의존 통합 테스트는 Pino logger module과 APP_FILTER를 같은 방식으로 등록하도록 공용 fixture를 사용한다. 단위·DB 통합 테스트에서 직접 생성하는 repository도 호출 검증 가능한 PinoLogger stub을 명시적으로 주입한다.

검증 증거

pnpm format:check, pnpm lint, pnpm test (직렬 실행, 57 suites / 264 tests), pnpm build, pnpm typecheck가 모두 통과했다. Pino 통합 테스트는 예외 로그와 HTTP 완료 로그의 동일 req.id, 허용된 name/message/stack 보존, response.token·password·DB parameter·cause secret의 비출력을 확인한다.

잔여 위험

동적 URL path 값은 로그에 남는다. 이후 credential/token path parameter를 추가하면 privacy review가 필요하다.
