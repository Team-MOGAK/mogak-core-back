기존 Cloud Run 설정 호환 및 Nest 배포 준비

목표변경 모델위험검증확인

목표

기존 Cloud Run 서비스, PostgreSQL 데이터, 환경변수 화면을 유지한 채 Nest가 기존 Spring 설정을 읽도록 한다. 컨테이너 이미지를 만들 수 있게 Dockerfile을 추가한다.

변경 모델

  • 기존 DB와 데이터는 변경·이관하지 않는다.
  • 현재 Nest 키도 계속 지원하므로 로컬 개발 환경은 그대로 동작한다.
  • Dockerfile은 Node 24.18 기반으로 빌드 산출물과 운영 의존성만 포함한다.

핵심 불변식과 위험

불변식: 기존 DB URL 자체는 변경하지 않는다. Nest는 JDBC 접두사만 Node PostgreSQL 드라이버가 이해하는 URL로 변환하며, 사용자명·비밀번호는 로그에 남기지 않는다.

이 작업은 DB 스키마, 운영 데이터, Cloud Run 트래픽을 바꾸지 않는다. 실제 트리거 변경과 배포는 사용자가 Cloud Build 화면에서 수행한다.

검증 계획

  1. 일반 PostgreSQL URL 우선과 Spring JDBC URL 변환 단위 테스트
  2. JWT/OAuth 기존·신규 키 호환 테스트
  3. pnpm format:check, pnpm lint, pnpm typecheck, pnpm build, pnpm test --runInBand, Docker 이미지 빌드

설계 통제 상태

미실시 — 로컬 확인은 정보용이며, 사용자는 기존 DB·주소 유지와 환경변수 호환 범위를 명시했다.

승인 상태

승인됨 — 2026-08-04 사용자 “빨리 고쳐. 배포하게”로 기존 DB·환경변수 호환 및 Dockerfile 추가를 승인했다.

동작 확인

기존 Cloud Run에 APP_DB_URL=jdbc:postgresql://...만 있을 때, Nest가 실제로 DB에 넘겨야 하는 URL은 무엇인가?


구현 결과

DATABASE_URL가 있으면 기존 Nest 동작을 유지한다. 없으면 APP_DB_URL에서 JDBC 접두사를 제거하고 APP_DB_USERNAME/APP_DB_PASSWORD를 결합한다. JWT는 JWT_SECRET 후 JWT_SECRET_KEY, Apple·Google은 복수형 키 후 단수형 키를 읽는다. main.ts는 Cloud Run의 문자열 PORT를 숫자로 변환해 0.0.0.0에 수신하며, Dockerfile과 .dockerignore를 추가했다.

검증 근거

  • pnpm format:check 통과
  • pnpm lint 통과
  • pnpm typecheck 통과
  • pnpm test --runInBand: 53 suites, 199 tests 통과
  • pnpm build 통과
  • docker build --tag mogak-core-back:local . 통과
  • 기존 형식의 APP_DB_*, JWT_SECRET_KEY, 단수형 OAuth 키만 주입한 컨테이너가 0.0.0.0:8080에서 부팅하고 GET /health → {"status":"ok"} 응답

잔여 위험

이미지 생성은 배포하지 않는다. Cloud Build 화면에서 이 저장소/브랜치와 기존 Cloud Run 서비스 이름을 연결하고, 기존 DB가 네트워크에서 도달 가능한지 확인해야 한다.

결정: 기존 DB와 키를 재사용

기존 Spring 서비스의 APP_DB_URL은 그대로 둔다. Nest는 그 값을 PostgreSQL 드라이버 형식으로만 바꿔 사용한다. APPLE_CLIENT_IDS 지원은 유지하며, 화면에 있는 APPLE_CLIENT_ID도 대체 키로 지원한다.
