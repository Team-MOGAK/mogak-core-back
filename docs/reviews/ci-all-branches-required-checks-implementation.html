1. 승인된 기준과 불변식

설계 문서의 핵심 흐름인 모든 브랜치 push·모든 PR·수동 실행·merge_group → 동일한 독립 검사 8개 → 엄격한 합산 → PR 필수 체크를 구현 기준으로 사용한다.

이번 구현은 DB 연결, 실제 DB 테스트, pnpm db:migrate, pnpm verify:local, Docker image push, Cloud Build/Run 호출을 실행 경로에 넣지 않는다.
승인 기준
기준수용 조건
적용 범위push는 모든 브랜치, PR은 대상 브랜치 필터 없음. draft PR을 제외하지 않는다.
독립성format, lint, typecheck, test, scripts, build, workflow-lint, image가 서로 needs 없이 실행된다.
병합 판정합산 job은 항상 실행하고 8개 결과가 모두 정확히 success일 때만 성공한다.
외부 영향읽기 권한만 사용하고 image는 local tag로 build만 한다. push·deploy·DB mutation은 없다.

구현 중 확인된 이슈
상태이슈대응
해결기존 workflow가 main 대상 PR만 실행하고 verify가 직렬이었다.PR target filter를 제거하고 8개 독립 job으로 분리했다.
해결aggregate가 실패한 needs 때문에 skipped로 끝날 수 있었다.if: always()와 step 내부 strict result 검사를 사용한다.

남음skip 지시문은 GitHub가 workflow 자체를 생략할 수 있다.팀에서 skip 사용을 금지하고 보호 브랜치에 required check를 적용한다. 보호되지 않은 개인 push를 workflow 하나로 강제할 수는 없다.

5. 검증 증거와 갭

  • CI=true pnpm install --frozen-lockfile, pnpm format:check, pnpm lint, pnpm typecheck, pnpm build, git diff --check가 통과했다.
  • pnpm test --runInBand는 최신 main 병합 후 57 suites / 274 tests 전부 통과했다.
  • pnpm test:verify-local는 3/3 통과했으며 실제 DB migration은 실행하지 않았다.
  • actionlint v1.7.12의 공식 macOS arm64 자산을 checksum 검증 후 실행해 workflow lint가 통과했고, YAML CI policy 구조 검사도 통과했다. GitHub Linux runner의 동일 단계도 두 원격 run에서 성공했다.
  • 로컬 Docker daemon은 현재 접근할 수 없어 image build 성공은 GitHub-hosted runner에서 확인한다.

두 원격 run 모두 head SHA bdc8f66000cebb2c36a14e93afef2cf72f5aafab에서 각 job과 aggregate가 성공했다. PR의 현재 check 목록에서도 Format, Lint, Typecheck, Test, Script tests, Application build, Workflow lint, Runtime image build, CI Required가 pass다.

6. 잔여 위험·운영 인수 조건

구현이 해결하지 않는 범위
위험남는 이유운영 인수 조건
DB 호환성·migration 실패사용자 제약에 따라 DB service와 migration을 CI에서 실행하지 않는다.별도 승인된 DB 검증/배포 설계에서 다룬다.
보호 규칙 우회저장소 파일만으로 GitHub ruleset과 관리자 리뷰 권한을 만들 수 없다.main ruleset에 PR 경유, CI Required, 최신 상태 요구, 우회자 정책, CODEOWNERS 승인을 설정한다.
실행 비용 증가모든 push와 PR에 독립 runner가 각각 실행되어 open PR push는 두 run이 될 수 있다.첫 운영 기간 비용·대기시간을 관찰한 후 별도 변경 승인으로 cache/범위를 재검토한다.
외부 action·base 갱신SHA 고정은 자동 업데이트를 하지 않는다.Dependabot 또는 정기적으로 release·digest를 검토하고 checksum을 함께 갱신한다.

개발자 이해 self-check는 이 문서의 구현 완료 조건이 아니다. 실제 인수는 로컬 게이트, 원격 push/PR run, 의도적 실패에서 다른 job 지속 및 aggregate 실패, 관리자 ruleset 적용 확인으로 판정한다.

7. 설계 기준 대비 변경 기록

승인 설계의 방향은 유지했다. 구현 세부로 actionlint를 release v1.7.12와 공식 SHA256로 고정했고, Dockerfile의 base image도 실제 manifest digest로 고정했다. 기존 단일 verify와 조건부 image job은 제거했다.

GitHub ruleset/CODEOWNERS는 계정·team을 임의로 지정하면 잘못된 보호를 만들 수 있어 저장소 파일 변경에서 제외했다. 이는 설계 이탈이 아니라 관리자 입력이 필요한 외부 설정의 보류다.

8. 개발자 운영 이해 확인

상태: 미실시. 아래는 구현 승인과 별개인 참고 질문이다. 답변 제출 없이도 구현은 진행할 수 있으며, 운영 인수 전에 팀이 확인한다.

확인할 질문
  1. PR 대상 branch가 main이 아니어도 CI Required가 실행되는가?
  2. lint가 실패해도 test·build·image가 실행되고 aggregate가 실패하는가?
  3. image build 성공이 DB migration·Cloud Run 배포 성공을 의미하지 않는 이유는 무엇인가?
  4. required check 등록만으로 보호되지 않은 branch push의 [skip ci]를 막을 수 없는 이유는 무엇인가?
