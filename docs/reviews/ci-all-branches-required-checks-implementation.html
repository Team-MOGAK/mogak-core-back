1. 승인된 기준과 불변식

기존 승인된 CI 재설계의 핵심 흐름인 모든 대상 브랜치 PR·수동 실행·merge_group → 동일한 독립 검사 8개 → 엄격한 합산 → PR 필수 체크를 구현 기준으로 사용한다. PR base 변경 재검증을 위한 edited trigger는 별도 설계 delta로 재승인 대기 중이며 현재 실행 경로에는 포함하지 않는다. PR 없는 개인 브랜치 push에는 자동 전체 CI를 실행하지 않는다.

이번 구현은 DB 연결, 실제 DB 테스트, pnpm db:migrate, pnpm verify:local, Docker image push, Cloud Build/Run 호출을 실행 경로에 넣지 않는다.
승인 기준
기준수용 조건
적용 범위현재 구현의 자동 전체 CI는 PR 대상 브랜치 필터 없음. PR 이벤트는 opened, synchronize, reopened, ready_for_review를 사용하고 draft PR을 제외하지 않는다. push 자동 trigger는 없다. edited base 재검증은 설계 delta로 별도 구현 대기 중이다.
독립성format, lint, typecheck, test, scripts, build, workflow-lint, image가 서로 needs 없이 실행된다.
병합 판정합산 job은 항상 실행하고 8개 결과가 모두 정확히 success일 때만 성공한다.
외부 영향읽기 권한만 사용하고 image는 local tag로 build만 한다. push·deploy·DB mutation은 없다.

5. 검증 증거와 갭

  • CI=true pnpm install --frozen-lockfile, pnpm format:check, pnpm lint, pnpm typecheck, pnpm build, git diff --check가 통과했다.
  • pnpm test --runInBand는 최신 main 병합 후 57 suites / 274 tests 전부 통과했다.
  • pnpm test:verify-local는 sandbox의 첫 실행에서 fake localhost listen이 EPERM으로 차단됐지만, 권한 경로 재실행에서 3/3 통과했으며 실제 DB migration은 실행하지 않았다.
  • actionlint v1.7.12의 공식 macOS arm64 자산을 checksum 검증 후 모든 workflow YAML에 실행해 통과했고, YAML CI policy와 composite action 계약 검사도 통과했다. GitHub Linux runner에서도 전체 workflow lint와 policy 검사가 성공했다.
  • 로컬 Docker daemon은 현재 접근할 수 없어 image build 성공은 GitHub-hosted runner에서 확인한다.

최신 원격 PR run 33961592042는 head SHA ab1a93b29dc720073c521b9c960948fc3712fbb4에서 Format, Lint, Typecheck, Test, Script tests, Application build, Workflow lint, Runtime image build, CI Required가 모두 pass다.

6. 잔여 위험·운영 인수 조건

구현이 해결하지 않는 범위
위험남는 이유운영 인수 조건
DB 호환성·migration 실패사용자 제약에 따라 DB service와 migration을 CI에서 실행하지 않는다.별도 승인된 DB 검증/배포 설계에서 다룬다.
workflow 정의 자기변경main ruleset은 active지만 1인 개발 정책상 승인 0·CODEOWNERS 미적용이다.현재는 사용자 결정으로 수용한다. 팀 협업 전환 시 CODEOWNERS와 최소 승인 정책을 추가한다.
PR 전 즉시 피드백 부재중복 제거를 위해 PR 없는 브랜치 push를 자동 검사하지 않는다.PR을 병합 경계로 사용하고 필요 시 manual run을 실행한다. 모든 raw branch push 자동 검사는 채택하지 않는다.
fork·merge ref 경계PR 이벤트를 기준으로 검사하므로 push-only의 branch check 재사용을 선택하지 않는다.read-only 권한과 외부 fork 승인 정책을 유지하고, merge queue 도입 시 merge_group을 실제 검증한다.
외부 action·base 갱신SHA 고정은 자동 업데이트를 하지 않는다.Dependabot 또는 정기적으로 release·digest를 검토하고 checksum을 함께 갱신한다.

개발자 이해 self-check는 이 문서의 구현 완료 조건이 아니다. 실제 인수는 로컬 게이트, 원격 PR run에서 단일 workflow 확인, 의도적 실패에서 다른 job 지속 및 aggregate 실패, base 변경 재검증과 ruleset 적용 확인으로 판정한다.

7. 설계 기준 대비 변경 기록

승인 설계의 trigger는 PR 중심으로 변경됐다. 기존 push+PR 전체 실행에서 pull_request 전체 실행으로 바꾸고 push 자동 trigger와 CI Push 표시를 제거했다. PR 없는 브랜치 push의 자동 검사를 포기한 대신 같은 SHA의 중복 runner를 없앴다. actionlint는 release v1.7.12와 공식 SHA256로 고정했고, Dockerfile의 base image도 실제 manifest digest로 고정했다.

이 변경은 기존 설계의 실행 경계를 좁히는 delta이므로 사용자의 PR 중심 전환 요청으로 재승인했다. DB 연결·migration·CD·image push 범위는 변하지 않는다.

GitHub ruleset은 저장소 외부 설정으로 적용했고, CODEOWNERS는 계정·team을 임의로 지정하면 잘못된 보호를 만들 수 있어 파일에 추가하지 않았다. 1인 개발 전제에서 승인 0·CODEOWNERS 미적용 위험을 수용하며, 협업 전환 시 재검토한다.

검토된 실행 경로

현재 구현은 PR/merge_group/manual 이벤트 → 8개 독립 job → if: always() aggregate → 결과가 모두 success인지 검사하는 step의 흐름이다. DB service·migration·CD 호출은 실행되지 않았고, runtime image도 push 없이 build만 수행된다. 최신 구현 검증 run 33961592042에서 동일 SHA에 push workflow가 추가되지 않는 것을 확인했다. base 변경 재검증은 다음 구현 단계다.

검증 증거와 공백

  • 기존 정상 경로인 push run 33953947957와 PR run 33954163267는 8개 job 및 aggregate 성공했다. trigger 변경 후에는 PR run 33961592042 1개만 생성되어 8개 job과 CI Required가 모두 성공했다.
  • trigger 변경 후 로컬 format, lint, typecheck, build, 57 suites / 274 tests, script tests 3/3, actionlint, YAML policy 검증 성공.
  • 실패 job 지속·aggregate 실패 차단은 의도적 실패 run으로 검증하지 않았다. 현재 성공 run은 정상 경로 증거다.
  • merge queue의 실제 merge_group 실행, base retarget 재실행, 실패 경로는 미검증이다. ruleset 존재·required check 등록은 현재 API로 확인했다.
