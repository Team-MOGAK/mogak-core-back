  • 기존 AppErrorCode를 이동해 단일 원본으로 사용한다. API import shim·DomainErrorCode/HttpStatus 제약·T001/Z002 alias와 HTTP 응답을 보존한다. shared는 Nest/Google/DB 의존성이 없다.

  • source project/service/log/subscription/producer/schema/environment/ERROR/50/eligible를 검증한다. timestamp는 필수, 비HTTP status는 optional이다. Node METHODS를 사용하고 revision을 제거했다.
  • Discord의 유효한 2xx와 message ID 확인 후 ACK한다. 네트워크·timeout·5xx·손상된 성공 응답·429는 Pub/Sub 재시도다. 429 대기는 DiscordClient의 숫자 하나로만 기억하며 재시작·여러 실행체 사이에 공유되지 않는다.
  • 영구 오류는 안전한 사유로 격리한 뒤 ACK한다. 격리 실패는 재시도다. 401/403/404는 event/status/errorId만 error 로그로 남기며 영속 차단을 만들지 않는다.

검증 공백·운영 제한

실제 GCP IAM·인증 push·Discord 수신·staging 전달은 검증하지 않았다. DB 동작 변경이 없어 DB 통합 검사는 실행하지 않았다. 로컬 검사·이미지 import 확인은 운영 전달 성공을 보증하지 않는다.

Discord 성공과 Pub/Sub ACK는 원자적이지 않으므로 중복 가능성이 있다. 429 대기는 재시작 시 사라지고 실행체 사이에 공유되지 않는다. native private DLQ에는 원본 로그가 남을 수 있다. 실제 배포 전에 기존 리소스와 개발/운영 분리를 확인해야 한다.

설계와 차이

승인된 현재 축소안과 차이 없음. Firestore 도입·PostgreSQL 대체안은 철회했다. payload의 임의 메시지를 공식 요약으로 신뢰하지 않으며 실제 운영 리소스는 변경하지 않았다.

외부 동작 근거: Cloud Run request timeout은 제한 초과 시 504를 반환하며 컨테이너 처리가 계속될 수 있음을 명시한다. SDK 시간 값은 설치된 @google-cloud/pubsub-api@0.3.0의 활성 publisher_client_config.json에서 확인했다.

최초 정적 리뷰 당시에는 HTTP 연결 종료·본문 지연·429 크기·격리 RPC 제한의 회귀 증거가 없었다. 후속 로컬 검증으로 실제 HTTP·429·RPC 옵션 증거를 추가했다. 실제 GCP 장애와 외부 발송은 검증하지 않았으며 이전 350개 통과를 현재 경로의 증거로 확대 해석하지 않는다.

유지 근거가 있는 구조: 공식 공통 메타데이터, 별도 ESM alerting 실행 단위, framework 없는 application service/port, 안전한 입력·출력 투영. 패키지나 adapter의 존재 자체가 문제가 아니라 기존 경로와 중복된 연결 및 실제 호출에 필요 없는 계약이 개선 대상이다. 최초 리뷰에서는 구현을 바꾸지 않았고 후속 명시 승인 뒤 수정했다.
