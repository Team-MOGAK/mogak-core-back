목표와 범위

판·모다라트 전환 화면에서 이번 주 진척을 한 번의 요청으로 표시하고, 주간 달력과 마이페이지는 선택 기능으로 남긴다. 기존 DB 모델을 재사용하며 새 저장 테이블은 만들지 않는다.

필수 계약

GET /api/modarats/{modaratId}/progress?date=YYYY-MM-DD. 입력 날짜가 속한 서울 시간대 주간(일요일~토요일)을 집계한다. 미래 날짜 회차도 분모에 넣는다.

{
  "result": {
    "weekStart": "2026-10-25",
    "percent": 36,
    "doneCount": 9,
    "plannedCount": 25,
    "mogaks": [
      { "mogakId": 12, "percent": 33, "doneCount": 2, "plannedCount": 6 }
    ]
  }
}
  • 모다라트 전체 합계와 그 안의 모각별 집계를 함께 반환한다. 회차가 없는 모각도 0으로 포함한다.
  • plannedCount는 해당 주의 루틴 회차와 start로 그날 추가한 회차의 수다.
  • doneCount는 계획 회차 중 SUCCESS 수다. percent는 done/planned의 정수 반올림이며 planned가 0이면 0이다.
  • 중복 방지 기준은 조각과 예정일의 조합(jogakId, scheduledDate)이다. 요일 테이블 조인 행 수를 그대로 회차 수로 세지 않는다.
  • B-13 실행 API 자체의 설계·수정은 이 범위에 포함하지 않는다. 다만 B-13에서 만든 그날의 회차를 조회 가능한 회차 데이터로 제공해야 이 집계에 포함할 수 있다. 이 데이터 연결은 구현 전 확인할 의존성이다.

선택 기능 — 이번 구현에서는 보류

  • GET /api/jogaks/summary?from=&to=: 달력용 날짜별 집계, 최대 42일.
  • GET /api/users/stats: 누적 totalDoneCount.

주요 경계와 검증

서울 기준 일요일 시작·토요일 종료, 주 시작/끝 날짜 경계, 미래 계획 회차 분모 포함, 같은 날 start 회차 포함, 요일 조인으로 인한 중복 미계수, 미완료·실패는 분모에만 포함, 빈 주 및 회차 없는 모각의 0 처리, 모다라트 소유권 검사를 검증한다.

승인된 보완안 — 주간 경계 날짜 오류

목표
주 경계가 4자리 연도 날짜 범위를 벗어날 때 서버 오류 대신 명시적인 잘못된 날짜 응답을 반환한다.
변경안
주 시작일과 종료일이 모두 0001-01-01~9999-12-31 범위의 날짜인지 확인한다. 범위를 벗어나면 기존 DomainErrorCode.INVALID_TARGET_DATE를 던진다. 이 오류는 기존 매핑에 따라 HTTP 400이다.
허용 경계
전체 일~토 주간을 표현할 수 있는 요청일은 0001-01-07부터 9999-12-25까지다. 그 밖의 달력상 유효한 날짜는 해당 주간을 이 API의 날짜 형식으로 표현할 수 없어 400으로 거부한다.
비목표
응답 계약, 집계 기준, DB 스키마, 다른 API의 날짜 허용 범위는 바꾸지 않는다. 새 오류 코드는 추가하지 않는다.
선택 근거
주간 전체가 기존 날짜 모델로 표현되지 않는 요청을 명확히 거부하는 한 가지 경로가 있다. 연도 10000 형식을 새로 도입하는 것보다 기존 계약을 보존하고 예상 가능한 400을 반환한다.
검증 계획
0001-01-01과 9999-12-31은 400으로 거부하고, 경계 안쪽인 0001-01-07과 9999-12-25 및 일반 날짜는 정상 주간 계산을 유지하는 단위 테스트를 추가한다. 컨트롤러 응답이 400인지 확인한다.

결정: 기존 오류 코드로 400을 반환한다. API 날짜 계약과 저장소 형식을 넓히는 대안은 채택하지 않았다.

의도와 실제 구현

모다라트 화면에 필요한 한 주의 전체·모각별 진척을 단일 읽기 API로 제공한다. 구현은 요청 날짜가 속한 서울 기준 일~토의 일정과 실행 기록을 조회해 (jogakId, scheduledDate)로 중복을 제거하고, SUCCESS를 완료 수로 집계한다. 선택 기능인 날짜별 달력 집계와 누적 사용자 통계, 별도 저장 테이블은 추가하지 않았다.

영향 경계와 불변식

  • 인증된 사용자의 모다라트 소유권을 확인한다.
  • 주간 분모에는 미래 예정 회차와 일정이 없는 start 실행 회차를 포함한다. 완료 수는 SUCCESS만 센다.
  • 회차가 없는 하위 모각도 0으로 반환한다. 같은 조각·날짜의 일정 및 실행은 한 회차로 센다.
  • 주간 날짜 계산은 날짜 문자열을 UTC 자정으로 처리해 서버 시간대에 의존하지 않는다.

코드 규모와 컨벤션

변경은 컨트롤러 경로와 요청 스키마, 응답 타입, 저장소 질의 필터, 서비스 집계, 집중 테스트로 한정된다. 기존 모각 서비스와 저장소 경계를 재사용하고 스키마 변경·범용 집계 프레임워크·선택 API를 만들지 않아 요구에 비례한다. 파일 구성, 명시적 반환 타입, Zod 요청 검증, repository port, readonly 결과 타입, 테스트 패턴은 주변 코드와 맞는다. 두드러진 컨벤션 위반은 보이지 않는다.

잔여 위험

한 주당 7일만 메모리에서 일정 행과 대조하므로 집계 작업량은 범위가 고정되어 있다. 소유권·모각·조각 관계와 일정·실행을 나눠 읽는 조회가 총 다섯 번이지만, 이 기능 요구에 필요한 관계를 가져오는 선형 조회다. 현재 근거만으로 쿼리 통합을 추가할 이유는 없다.
