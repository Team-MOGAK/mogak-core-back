승인된 범위와 불변식

  • 날짜 범위 최대 366일, 피드·게시글 size 최대 100, offset 계산은 safe integer 범위다.
  • 네트워크 요약 feed는 댓글 행을 조회하지 않는다.
  • 같은 부모에 대한 동시 생성은 부모 행 잠금 뒤 용량을 재검사해 8개 상한을 넘지 않는다.
  • 생성·삭제·탈퇴의 hierarchy mutation은 modarat → mogak → jogak 순서로 필요한 행만 잠근다.
  • 모든 쓰기 transaction은 관련 사용자 행을 ID 오름차순으로 먼저 잠그고, 사용자 자체 수정은 처음부터 FOR UPDATE를 취득한다. 탈퇴 transaction은 advisory gate와 사용자 FOR UPDATE를 먼저 취득한다.
  • post·comment·like는 행위자·post author·현재 execution owner를 잠근 뒤 post를 잠근다. 같은 (post,user) toggle은 FOR NO KEY UPDATE로 직렬화한다.
  • malformed calendar date는 날짜 산술 전에 비예외 predicate로 거부해 HTTP 400/Z005로 수렴한다.
  • 기존 페이지·cursor 이름과 성공·오류 envelope을 유지한다.
  • 동일 provider·subject 로그인 경쟁은 PostgreSQL 오류가 cause로 감싸져도 exact identity 재조회로 수렴한다.

잔여 위험

운영 DB의 lock 대기·transaction duration·pool 대기 관측과 migration journal이 없는 기존 설치의 정식 upgrade 절차는 별도 운영 게이트다. 애플리케이션 writer는 공통 규약을 따르지만 raw SQL이나 규약을 우회하는 새 writer는 자동으로 보호되지 않는다. 외부 storage가 재활성화되면 profile upload/delete와 탈퇴의 외부 효과를 별도 설계해야 한다.
