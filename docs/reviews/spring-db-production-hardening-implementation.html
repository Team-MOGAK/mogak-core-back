기준선과 승인 범위

이번 변경은 중첩 unique 매핑, JWT secret 최소 길이, PostgreSQL Pool error/timeout, DB 오류 로그 정제, qs 잠금 파일 갱신, Multer 전이 취약점 완화와 multipart 배열 인덱스 상한을 포함한다. migration·세션 보존·readiness·Cloud Run CD·운영 DB 실행은 보류한다.

현재 구현

  • JwtTokenService가 JWT_SECRET 또는 legacy JWT_SECRET_KEY를 UTF-8 32바이트 이상인지 기동 시 검증한다. 누락·공백·짧은 값은 명확한 오류로 거부한다.
  • database.provider.ts가 두 연결 문자열 경로에 동일한 Pool을 사용하고 연결 5초·쿼리/statement 10초·idle 30초 timeout과 idle client error listener를 적용한다. Pool 오류 로그에는 SQL·message·stack·params 없이 허용된 SQLSTATE/식별자만 남긴다.
  • GlobalExceptionFilter가 Drizzle 오류와 중첩 cause를 순회해 허용된 DB 메타데이터만 기록하고, DB 오류의 원문 message·stack을 Database operation failed로 대체한다. Multer 2.3의 multipart 입력 거부 코드도 안전한 400 응답과 허용된 코드만의 로그로 변환한다. Pino 직렬화 결과도 sentinel 검증을 통과했다.
  • UserRepository가 순환 방지 cause 순회로 23505/users_nickname_unique를 DuplicateNicknameException으로 변환한다.
  • pnpm-lock.yaml의 전이 qs를 6.16.0으로 갱신하고, 루트 pnpm.overrides로 Nest의 전이 multer를 2.3.0으로 고정했다.
  • 프로필·게시글 업로드 정책에 limits.fieldArrayIndexLimit: 0을 적용하고, 실제 과대 multipart 배열 인덱스가 저장소 호출 전에 거부되는 회귀 테스트를 추가했다.

구현 상태

구현 완료 · 승인된 G10/G13-A/G14-A 최소 범위의 코드·테스트·잠금 파일 반영과 로컬 검증을 마쳤다. 운영 DB·GCP 변경은 수행하지 않았고, 운영 제어는 아래 잔여 이슈 해결 전까지 보류한다.

검증 공백

실제 운영 DB·GCP resource·traffic은 의도적으로 검증하지 않았다. pnpm verify:local 전체 실행과 migration은 운영 데이터 변경을 포함하므로 수행하지 않았다. 통합 테스트는 로컬 격리 PostgreSQL에서 실행했다.

잔여 위험

multer 감사 blocker는 2.3.0 override와 업로드 경계 검증으로 해소됐다. 운영 제어를 계속 보류하는 항목은 static /health와 readiness 분리, legacy weekday migration, 세션 누적 정책, Cloud Run rollout 순서다. 이 범위에서는 운영 DB·GCP 리소스를 추측해 변경하지 않는다.

최종 읽기 전용 리뷰

자기 변경을 승인된 설계·실제 diff·검증 출력과 대조했다. 구현된 G10/R2/R5/R7/R9/G14 항목에서 추가 concrete code finding은 확인하지 못했다. Multer 감사 blocker는 해소됐지만, 보류한 운영 항목 때문에 릴리스 차단 상태는 유지한다.

상태: 운영 제어 보류. 승인된 기술 구현, Multer 감사 해소와 로컬 검증은 완료했다. 실제 운영 DB·GCP 변경과 별도 운영 설계 항목이 남아 있으므로 배포 승인으로 전환하지 않는다.
