승인된 기준선과 불변식

  • PR16을 먼저 병합하는 기반으로 두고 PR17은 PR16 위의 증분 PR로 만든다.
  • PR16의 `/health/ready`, legacy migration preflight/rollback, session cleanup을 삭제하지 않는다.
  • PR17의 page/date bound, offset overflow 방지, transaction/advisory lock과 lock ordering을 유지한다.
  • 공통 예외·요청 schema·서비스·auth·DB provider는 두 계약을 합친 단일 구현으로 남긴다.
  • merge commit을 사용하고 force push하지 않는다. 운영 DB·Cloud Run은 실행하지 않는다.

현재 구현

PR17 작업 트리에 PR16을 --no-ff로 통합하고 15개 공통 충돌을 기능 보존 기준으로 해결했다. 결과 merge commit은 a4fddeae이며 PR17 원격 head에 push했다. 기준 head는 PR16 518bd5e, PR17 df90cd8, 공통 기준 848f639로 고정되어 있다.

구현 상태

원격 CI 통과 · 순차 병합 대기. PR16은 main 기준으로, PR17은 PR16 브랜치 기준으로 각각 MERGEABLE/CLEAN이다. PR16을 먼저 병합한 뒤 PR17을 병합하면 된다.

검증 공백

현재 환경에 DATABASE_URL/APP_DB_URL가 없어 PostgreSQL integration test는 실행하지 않았다. 운영 DB migration, readiness probe traffic, Cloud Run rollout, 원격 PR merge 자체는 로컬 게이트가 증명하지 않는다.

잔여 위험

DB 통합 검증은 환경에 데이터베이스가 없어 남아 있다. 실제 병합 버튼 실행은 담당자가 PR16→PR17 순서로 수행해야 하며, 통합 과정에서는 force push와 운영 DB 실행을 하지 않았다.

구현 이해 점검

점검 완료. PR16 first merge 결과로 readiness·migration·session cleanup을 보존했고, 공통 오류·pagination·auth 계약과 conflict marker 제거를 확인했다. 로컬 API 시나리오 3개와 원격 CI 9개가 통과했으며 PR17 base 전환도 확인했다. 실제 PR 병합은 PR16→PR17 순서로 남아 있다.
