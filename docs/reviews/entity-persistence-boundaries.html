목표

테이블별 PK·컬럼·제약은 Drizzle table 파일 한 곳에서 확인하고, 동일 필드의 domain entity 재선언을 제거한다.

변경 모델

schema/<feature>/<table>.table.ts는 DB 정의와 ORM 모델의 정본이다. 조회 형태가 application 결과와 같은 단순 필드 묶음이면 repository가 그대로 반환한다. 값의 의미가 바뀌는 지점만 domain VO 객체의 parse()가 검증한다. 별도 mapper와 기계적 toXxx는 만들지 않는다.

핵심 위험과 불변식

application은 Drizzle과 DB 조회 형태를 import하지 않는다. DB 문자열을 도메인 값으로 바꾸는 책임은 VO에만 둔다. Repository는 질의·저장·영속성 오류 변환만 담당하고, 단일 사용 *Row·mapper·identity 변환을 두지 않는다.

검증 증거

  • pnpm typecheck 통과
  • pnpm lint 통과
  • pnpm test --runInBand test/mogaks 8 suite, 40 test 통과 (VO의 저장값 검증 포함)
  • 전체 pnpm test --runInBand는 52 suite 중 51 suite, 199 test 통과 후 게시글 multipart 계약 테스트 1건이 5초 timeout으로 실패했다. 해당 테스트 단독 재실행은 1 suite, 11 test 통과했다.
  • git diff --check 통과, 모각 source에서 *Row·PersistenceMapper·repository toXxxResult 참조가 남지 않음을 확인했다.

구현 결과

전용 persistence mapper와 단일 사용 *Row를 제거했다. 조회 형태가 application 결과와 같은 모다랫·모각·소유 조각은 repository가 직접 반환한다. JogakExecutionStatus, JogakScheduleType, JogakScheduleWeekdayName VO 객체가 parse()로 실행 상태·일정 종류·요일을 검증하고, repository는 저장된 잘못된 값을 infrastructure MogaksPersistenceException으로 변환한다. 레이어 검사에는 domain/application/presentation의 database 역의존과 infrastructure의 presentation 역의존 차단도 추가했다.
