Mogak 카테고리 tagged union 구현 제어

목적
Mogak PATCH 카테고리 선택을 모호함 없이 전달한다.
사용자
MOGAK 모바일·서버 API 개발자
문제
{ code?, name? }가 두 카테고리 형태를 구분하지 못하고 controller 변환을 요구한다.
핵심 흐름
PATCH 요청 검증 → SYSTEM/CUSTOM 명령 전달 → 기존 카테고리 해석·저장
강도
Standard
단계
구현 완료
승인 설계 기준선

승인 기준

PATCH /api/mogaks/:mogakId의 category는 { type: 'SYSTEM', code } 또는 { type: 'CUSTOM', name }만 받으며, 생략하면 보존한다. 승인: 2026-08-22 KST.

현재 구현

mogakPatchRequestSchema가 strict discriminated union으로 SYSTEM/code 또는 CUSTOM/name만 받는다. PatchMogakCommand도 같은 category 표현을 사용하며, controller는 요청을 직접 service로 전달한다. service가 저장용 categoryCode 또는 customCategoryName으로 해석한다. 얕은 공통 MergePatch<T> 타입을 도입해 Modarat·Mogak·marketing-consent·Jogak PATCH가 요청을 직접 전달한다. Jogak scheduleType은 Zod enum이 검증한다.

구현 상태

구현 완료. 스키마·명령 타입·controller·계약 테스트를 갱신했다.
