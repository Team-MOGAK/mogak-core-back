목표와 비목표

요일·단일 일정·일정 이력을 역할별 객체로 만들고, 검증된 상태가 외부 배열 별칭 때문에 바뀌지 않게 한다. 기존 HTTP JSON 형태와 repository port의 배열 계약은 경계에서 유지한다.

선택한 범위와 파일 계획

  1. jogakWeekdays.vo.ts에 immutable JogakWeekdays, onceSchedule.vo.ts에 OnceSchedule, routineSchedule.vo.ts에 RoutineSchedule, jogakSchedules.vo.ts에 JogakSchedules를 둔다. 공용 snapshot은 jogakSchedule.vo.ts에 남긴다.
  2. DB row를 조립하는 groupScheduleRows는 raw row를 HydratedScheduleRecord { scheduleId, schedule, metadata }로 번역한다. 영속 데이터가 규칙을 위반하면 기존 persistence 오류 경계에 맞게 번역한다.
  3. getDetail은 현재/최신 일정, update는 수정 대상/후속 일정, occurrence projection은 각 타입의 occursOn(date)으로 판단한다. metadata 결합과 응답 변환은 application service에 남긴다.
  4. repository/API에는 raw array를 계속 전달한다. 기존 public JSON 필드명·요일 입력 순서·오류 코드는 유지한다.
경계 규칙: JogakSchedules는 scheduleId, 모각·조각 제목, 색상, 카테고리, DB row를 소유하지 않는다. 이 metadata는 application의 HydratedScheduleRecord에 남긴다. ConsentSelections는 외부 활성 항목 스냅샷과의 관계 검증이 핵심이므로 이번 변경에서 제외한다.

핵심 위험과 실패 처리

가장 큰 위험은 내부 타입을 바꾸며 기존 API 배열이나 persistence 저장 배열까지 객체로 흘려보내는 것이다. 따라서 toArray()/toSnapshot()은 경계에서만 사용하고, 기존 request/response DTO는 변경하지 않는다.

저장된 weekday가 중복·지원 불가이면 조용히 정규화하지 않는다. 현재 저장 값 오류 처리 관례에 맞는 persistence 예외로 번역하여 데이터 이상을 드러낸다. 요청 값의 오류 코드 매핑(ROUTINE_WEEKDAYS_REQUIRED, INVALID_SCHEDULE)은 유지한다.

대표 일정 결정: GET /api/jogaks/:jogakId는 캘린더의 일일 발생 목록이 아니라 조각의 설정 상세(isRoutine, days, startDate, endDate, schedules)를 반환한다. 이력에 오늘 유효한 RoutineSchedule과 과거 OnceSchedule이 함께 있으면 활성 루틴을 대표로 선택한다. 활성 루틴이 없을 때만 최신 이력을 fallback으로 쓴다. 일일 발생·실행 기록은 별도 GET /api/jogaks?date=... 및 daily_jogak 경계다.
