승인 기준선

승인된 설계 · 2026-10-15 사용자 “브랜치 따고 워크트리 따서 구현 작업 진행해”를 저장소 구현·로컬 검증의 승인으로 기록했다. 실제 운영 GCP 변경과 Discord 전송은 수행하지 않았다.

현재 구현

  • pinoHttp.options.ts: 숫자 level과 native severity, schemaVersion/service/environment/producer, HTTP 상태별 레벨과 5xx fallback.
  • globalException.filter.ts: 최종 매핑 상태로 warn/error를 분류하고 response-local Symbol marker로 대표 5xx를 지정한다.
  • database.provider.ts: 필수 Pino DI와 생성 시 캡처한 child logger, 독립 UUID, 안전한 DB 식별자만의 오류 기록.
  • apps/alerting: 독립 ESM TypeScript 패키지, 엄격한 Pub/Sub 입력 검증, 허용 필드 메시지, Discord client, Firestore 제어, 안전한 quarantine.
  • infra/error-log-relay: 기본 plan 배포 도구, 명시적 apply와 선행 점검, 인증된 push/IAM, 비활성 sink, 채널 초기화·재개·중단·버전 교체 도구.
  • pnpm workspace와 독립 Docker 빌드, CI 및 로컬 검증 흐름에 relay·infra 검증을 연결했다.

운영 가이드에서 설정, 선행 리소스, DLQ, 수동 replay, secret 교체와 중지 절차를 확인할 수 있다.

구현 상태

저장소 구현·로컬 게이트·최종 재리뷰 완료. 리뷰 finding의 수정과 재검증 증거를 아래에 기록했다. 실제 운영 배포·staging webhook 수신은 미실시다. 운영 source 식별자는 읽기 전용으로 project workvoys, service mogak-spring, region asia-northeast3를 확인했다.

설계 차이

승인된 동작·개인정보 경계·전달 보장은 유지한다. 독립 pnpm package와 명시적 설정 기반 배포 도구로 구체화했다. Firestore API 비활성화는 운영 전제조건으로 기록했으며 자동 활성화나 데이터베이스 생성을 수행하지 않는다.

범위와 의도

warn과 error를 최종 실패 결과로 구분하고 운영 API의 대표 ERROR/50만 별도 relay를 통해 Discord에 전달한다. API·relay·Firestore 상태·Pub/Sub·Cloud Run·Docker·CI 경계를 검토했다. 실제 운영 배포와 전송은 범위 밖이다.

실제 구현 흐름과 불변식

발견 사항

코드 리뷰 finding 수정 이력 (관찰 내용은 수정 전 기준)
ID / 심각도 / 상태근거·발생 조건·영향최소 수정 방향
EWR-1 · P1 · blocker · fixed구독 자동 만료 정책을 해제해야 함

source와 quarantine/DLQ의 create/update argv에 expiration-period가 없고 postflight에도 수명 검사가 없다. Pub/Sub 기본값은 subscriber activity 없는 31일 뒤 삭제다. 정상 운영에서 ERROR가 31일 이상 없으면 source push 구독이 삭제되어 다음 장애가 Discord로 전달되지 않는다. 보존 구독도 operator consume이 없으면 만료될 수 있다. message-retention=7d는 구독 수명 설정이 아니다.

세 구독 create/update에 --expiration-period=never를 명시하고 postflight 및 계획/재배포 테스트에서 확인한다.
EWR-2 · P2 · blocker · fixed사후 검증 전에 sink를 활성화하고 실패 시 활성 상태를 남김

--activate-sink 실행은 전체 operation loop에서 --no-disabled를 먼저 적용한 뒤 postflight한다. 기존 source subscription이 다른 topic에 연결된 경우 update로 topic을 바꿀 수 없으므로 마지막 postflight에서 실패한다. 예외 처리나 sink rollback이 없어 오류를 반환한 뒤에도 sink는 활성화되어 있고 원하는 topic에는 소비자가 없어 알림이 전달되지 않는다. extra invoker 등 다른 postflight 실패도 활성 상태를 남긴다.

sink는 비활성 상태에서 writer 권한과 managed resource postflight를 완료한 뒤 마지막 단계로 켠다. postflight 실패 시 활성화하지 않는 fake apply 사례를 추가하고 기존 구독의 immutable topic 충돌을 명확히 거부한다.
EWR-3 · P3 · non-blocking risk · fixed알림 eligibility가 빠진 ERROR의 계약 누락 탐지가 없음

현재 두 직접 error 호출에는 alertEligible=true가 있어 현존 로그 유실은 확인되지 않았다. 다만 승인 설계가 약속한 새 error 호출 계약 검사와 조회 가능한 누락 지표가 없다. 향후 eligibility를 빠뜨린 ERROR는 sink에서 제외되어 relay quarantine으로도 발견할 수 없다.

source error 계약 정적 검사와 sink 바깥의 ERROR 중 alertEligible 누락을 찾는 Logging query/metric을 추가한다. explicit false는 의도된 중복 상세로 구분한다.
EWR-4 · P1 · fixed만료 정책 누락을 영구 구독으로 오판isNeverExpiring이 undefined/null을 거부하도록 수정했다. 세 구독의 누락·기본 TTL 거부, 명시적 빈 policy 허용, 실패 시 sink 미활성화 테스트로 검증했다.
EWR-5 · P2 · fixedDiscord 성공 메시지 ID 감사 기록 누락wait=true 성공 응답을 크기·시간 제한 안에서 읽어 검증한 ID만 전달·기록한다. 성공/손상/누락/초과 응답과 로그 허용 필드를 테스트했다.

검증 증거와 공백

이번 PR 전 fresh 검증: API 61 suites / 316, relay 18, infra 24, script 3 — 총 361 tests 통과. format/lint/API·relay typecheck와 build, Docker 두 이미지 및 network=none import, actionlint/CI 정책, deploy/channel plan 통과. 직접 503의 실제 Nest/Pino stream 한 건과 source ERROR 정적 계약 검사를 추가했다. 독립 no-write 재리뷰와 SHA-256 스냅샷을 확인했다. 실제 GCP IAM·전파 지연·staging/Discord 수신은 미검증이다.

공식 근거: Pub/Sub 구독 만료 기본값과 subscriber activity, expiration-period=never, 기존 subscription topic은 변경 불가.

잔여 위험과 리뷰 판단

승인된 at-least-once 중복과 장기 장애 DLQ 이동은 별도 제한이다. 이번 finding을 수정해도 실제 운영 경로 검증을 대신하지 않는다.

판단: 추가 concrete finding 없음. EWR-1~5를 수정하고 독립 재리뷰를 완료했다. 실제 운영 검증 공백은 유지하며 이 결과는 운영 배포나 병합 승인이 아니다.
