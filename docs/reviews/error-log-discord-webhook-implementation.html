error 로그 Discord 웹훅 구현 통제

설계 기준선: error 로그 Discord 웹훅 전달 설계. 구현 대상: PR #19, 브랜치 codex/error-log-discord-webhook, 시작점 f72483386078f4d56b073579d46bd20e13b32ad4.

사용자 승인: 2026-10-19 “개선 ㄱ”. 승인 범위는 설계 문서의 동일 프로세스·비동기 best-effort webhook 구조로 PR을 재구성하는 것이다.

승인 기준선과 불변 조건

  • 백엔드 API와 같은 Node/Nest 프로세스에서 논리 모듈로 실행하며 하나의 기존 backend 이미지/Cloud Run 서비스로 배포한다.
  • 5xx와 요청 밖 DB pool error만 canonical event를 한 번 전송 요청한다. 4xx는 warn이며 전송하지 않는다.
  • Discord 전송은 API 응답을 기다리지 않는다. timeout은 2초, retry 없음, 영속 큐 없음. 프로세스 종료나 Discord 장애에서 유실 가능성을 수용한다.
  • DISCORD_WEBHOOK_URL이 없거나 유효하지 않으면 시작 경고를 기록하고 alerting만 비활성화한다. API는 계속 실행한다.
  • Discord에는 allowlist 요약만 전송한다. exception message/stack, SQL/parameters, request body/query, 식별자가 포함된 실제 URL, 자격 증명, webhook URL을 보내거나 로그에 기록하지 않는다.
  • 실제 Discord 발송, Secret Manager 생성·회전, GCP/IAM/Cloud Run 변경은 하지 않는다.

구현 결과

AlertingModule을 libs/modules/src/infrastructure/alerting에 추가하고 API 예외 필터·Pino 5xx fallback·DB pool error에 연결했다. 알림 sender는 Discord webhook을 한 번 호출하고 실패를 안전하게 로그로 남긴다. 독립 apps/alerting, relay Dockerfile, Pub/Sub/Cloud Build provisioning과 relay runbook을 제거했다. root Dockerfile 유지, CI는 backend runtime image 한 개만 빌드한다.

이슈 및 잔여 위험

항목상태내용
독립 relay 아키텍처해결같은 backend 프로세스 안의 모듈로 대체. 독립 이미지·서비스·Pub/Sub 배포 경로 제거.
4xx/중복 알림해결4xx는 제외. 예외 필터가 대표 5xx를 소유하고 완료 로그는 marker가 있으면 재전달하지 않는다.
Discord 장애·재시작수용비동기 best-effort라 전송 실패·timeout·프로세스 종료 시 유실 가능. 재시도·영속 queue 없음.
운영 secret배포 시 확인기존 backend runtime에 Secret Manager의 DISCORD_WEBHOOK_URL 주입 필요. 실제 secret/서비스 설정은 이 변경에서 만들지 않았다.
운영 image build환경 제한로컬 Docker daemon은 실행되지 않아 로컬 image build는 생략했다. GitHub Actions Runtime image build는 통과했다.
