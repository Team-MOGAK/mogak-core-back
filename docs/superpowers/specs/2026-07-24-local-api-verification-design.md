# 로컬 실제 API 검증 설계

## 목적

한 번의 `pnpm verify:local` 실행으로 Nest 서버를 실제 포트에 기동하고, 인증된 HTTP API에 경로 파라미터·쿼리·JSON 또는 multipart 바디를 순서대로 전송해 핵심 사용자 흐름을 확인한다.

## 범위

기존 단위 테스트, E2E 헬스체크, PostgreSQL 통합 테스트는 그대로 실행한다. 그 뒤 별도의 외부 HTTP 시나리오가 메타데이터, 모다랏·모각·조각, 실행 상태, 게시글·댓글·좋아요, 팔로우 API를 검증한다. 실제 Apple·Google·Kakao ID 토큰을 요구하는 소셜 로그인 요청은 포함하지 않는다.

## 인증과 데이터 격리

시나리오는 `mogak_test` 데이터베이스만 사용한다. 실행마다 무작위 접미사가 붙은 두 `USER` 사용자와 한 활성 세션을 직접 준비하고, 현재 `JWT_SECRET`으로 Access Token을 발급한다. 이는 테스트 전용 초기화일 뿐 테스트용 HTTP 엔드포인트를 추가하지 않는다. 종료 시 생성한 두 사용자를 삭제해 FK cascade로 관련 데이터를 함께 정리한다. 일반 로컬 DB `mogak_local`과 운영 DB는 사용하거나 비우지 않는다.

## 실행 흐름

1. PostgreSQL을 준비하고 정적 검사·빌드·기존 Jest 테스트를 실행한다.
2. `mogak_test`에 최신 Drizzle 마이그레이션을 적용한다.
3. 임시 포트에서 `node dist/main.js`를 `mogak_test` 연결로 시작한다.
4. 준비된 Access Token을 `Authorization: Bearer` 헤더에 넣고, 이전 응답의 ID를 이후 URL과 바디에 전달하며 API 흐름을 호출한다.
5. 각 요청의 HTTP 상태, 성공 응답 형식, 핵심 필드를 검사한다. 실패 시 요청 이름·메서드·경로·상태·응답을 출력하되 인증 토큰은 출력하지 않는다.
6. API 프로세스와 생성한 테스트 픽스처만 정리한다. Docker 컨테이너와 볼륨은 계속 유지한다.

## 시나리오

- `/health`, 공개 메타데이터
- 모다랏 생성·조회·수정, 모각 생성·조회
- 일회성 조각 생성·조회, 실행 시작·완료
- multipart `request` 바디를 통한 게시글 생성, 게시글 조회·수정, 댓글 생성·수정, 좋아요 생성·취소
- 두 번째 테스트 사용자를 대상으로 팔로우 생성·조회·취소

## 실패 정책

어떤 API 요청이든 예상 상태 또는 응답 조건과 다르면 즉시 실패한다. 정리 실패는 원래 실패를 가리지 않고 추가 오류로 출력한다. 성공 시 호출한 시나리오 이름을 순서대로 표시한다.
