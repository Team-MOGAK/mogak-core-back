# API 악용 방어 설계

## 목적

공개 앱 API에서 확인된 두 가용성 위험을, 기존 HTTP 계약과 Storage 보류 결정을 바꾸지 않고 줄인다.

- multipart 파일이 처리되기 전에 메모리를 무제한 점유할 수 있는 위험
- 로그인·토큰 갱신 같은 공개 인증 API를 무제한 호출할 수 있는 위험

이 작업은 SQL 인젝션, CSRF, HTML 렌더링/XSS 처리 방식을 바꾸지 않는다. 현재 API는 헤더 토큰 인증과 JSON 응답만 사용한다.

## 고려한 방식

1. **권장: 라우트 단위 multipart 제한 + 프로세스 내 제한기**
   - 기존 URL, 필드명, 응답 envelope를 유지한다.
   - 새 인프라·DB·환경 변수 없이 즉시 적용한다.
   - 여러 인스턴스에 걸친 완전한 전역 제한은 제공하지 않지만, 현재 단일/소수 인스턴스 운영에 적합하다.

2. Storage가 준비될 때까지 multipart 라우트를 제거한다.
   - 가장 강한 차단이지만, 기존 클라이언트가 기대하는 빈 파일 처리와 `Z006` 비활성 Storage 경계를 깨므로 채택하지 않는다.

3. Redis 또는 API Gateway 제한기를 즉시 도입한다.
   - 다중 인스턴스에서 가장 강하지만, 현재 저장소와 배포 구성이 없는 상태에서 새 운영 의존성을 도입한다. 실제 다중 인스턴스/서버리스 분리 시 후속 작업으로 둔다.

## 확정 설계

### 업로드 경계

- 게시글 `multipartFile`: 최대 5개, 각 5 MiB
- 프로필 `multipartFile`: 최대 1개, 5 MiB
- 허용 MIME은 `image/jpeg`, `image/png`, `image/webp`만 사용한다.
- 제한은 Multer 인터셉터에서 적용하므로, 비활성 `StoragePort`가 `Z006`을 반환하기 **전에** 요청을 차단한다.
- 파일이 없거나 0 byte인 기존 요청은 계속 허용한다. 실제 파일은 여전히 Storage 비활성 경계에서 `Z006`을 반환한다.
- 파일 수/크기/MIME 위반은 현재 전역 예외 변환을 거쳐 `400` BaseResponse로 반환한다. 별도 공개 에러 코드는 만들지 않는다.

실제 Storage 구현이 생기면 MIME 검사만 신뢰하지 않고 이미지 매직 바이트 검사와 저장소 측 크기 제한을 추가한다. 이 작업에서는 파일을 저장·변환하지 않는다.

### 요청 제한

작은 프로세스 내 고정 윈도우 제한기를 공통 HTTP 계층에 둔다. 제한기 상태는 최대 엔트리 수를 두고, 윈도우가 지난 엔트리를 제거해 임의 키로 메모리를 점유하는 문제를 피한다.

| 경로 | 키 | 제한 |
| --- | --- | --- |
| `POST /api/auth/login`, `POST /api/auth/:provider/login` | 요청 IP | 분당 10회 |
| `POST /api/auth/refresh` | 요청 IP | 분당 10회 |
| `POST /api/users/nickname/verify` | 요청 IP | 분당 30회 |

- 한도를 넘으면 `429`와 기존 BaseResponse를 반환한다.
- 닉네임 검증은 가입 전에도 호출하는 공개 계약이므로 IP를 키로 쓴다. 이 경로에 인증 가드를 추가하지 않는다.
- IP는 Express가 제공하는 `request.ip`만 쓴다. 배포 프록시 신뢰 설정은 이 변경에 추측으로 넣지 않는다.
- 프로세스 내 상태이므로 재시작 시 초기화되고, 다중 인스턴스에서는 인스턴스별로 적용된다. 서버리스/다중 인스턴스 배포 시 Redis 또는 게이트웨이 제한기로 교체한다.

## 테스트

- 게시글의 여섯 번째 파일, 5 MiB 초과 파일, 허용되지 않은 MIME이 애플리케이션 서비스에 도달하지 않고 실패한다.
- 프로필의 5 MiB 초과·허용되지 않은 MIME이 실패한다.
- 정상적인 빈 파일/텍스트 전용 게시글 계약은 유지한다.
- 각 인증 경로가 한도까지 성공하고 다음 요청에서 `429`가 된다.
- 닉네임 검증은 한도까지 성공하고 같은 IP의 다음 요청에서 `429`가 된다.

## 범위 밖

- Redis·외부 rate limiter·API Gateway 정책
- Storage 제공자, signed URL, 파일 바이러스 검사, 이미지 변환
- 웹 쿠키 인증 및 CSRF 토큰
- DB 인덱스·제약 추가
